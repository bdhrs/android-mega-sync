- 2026-09-02 [WORKFLOW] Building a local-folder browse/pick UI, first reused SafLocalStore.snapshot() (full recursive walk + per-file content fingerprint) for a picker that only needed names — 20s+ on a real vault. Swapping to a name-only recursive walk was still ~20s, because every SAF listFiles() call is its own ContentProvider round trip; only switching to true one-directory-at-a-time lazy loading fixed it. Should have designed for lazy per-directory loading from the start for any SAF-backed browsing UI, not reused the sync engine's full-snapshot APIs.
- 2026-09-02 [POSITIVE] Running an independent fresh subagent for review (in parallel with CodeRabbit) after implementing a UI feature caught a real concurrency bug (stale background-load race in a picker Activity) that manual device testing and the original author both missed. Worth keeping as standard practice for UI thread/async code.
- 2026-09-02 [WORKFLOW] Rewrote a SAF directory listing to a single cursor query and indexed the columns positionally, in the order they were requested. A ContentProvider is not required to honour the projection order, and the platform's own default document projection uses a different one — so on any non-default storage provider the code would have read mime types as filenames and planned a remote deletion of the whole vault. On-device testing passed because the external-storage provider does echo the projection. Lesson: read cursor columns by name, and never let "it worked on my device" stand in for "this provider contract guarantees it".

Worth keeping both, and worth telling the auditor which claims to attack.
